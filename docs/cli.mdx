```sh
lotus run hello.lt
lotus build hello.lt
./hello.lt.out
lotus check hello.lt
```

| Command | Result |
| --- | --- |
| `new NAME PATH` | Create `PATH/NAME/main.lt` from the starter template |
| `run FILE` or `FILE` | Execute through JIT; no binary is created |
| `build FILE` | Create `<FILE>.out` on macOS/Linux or `<FILE>.exe` on Windows; do not execute it |
| `check FILE` | Parse and type-check; do not generate or execute code |

For `run`, `build` and `check`, pass one source file. Relative paths use the working directory; quote paths containing spaces. Use `./-example.lt` for a name starting with a dash. Program arguments and stdin source input are not supported.

Successful `build` and `check` are silent. Normal `run` prints program output. Failures return a nonzero exit code and diagnostics on stderr.

## Create a project

```sh
lotus new hello .
lotus run hello/main.lt
```

Creates `hello/main.lt` with a welcome comment and `print("Hello, World!")`. `PATH` must be an existing directory; `NAME` is a folder name, not a path. Existing files or folders with that name are never overwritten.

## Options

| Option | Purpose |
| --- | --- |
| `--libs DIR` | Select the native library directory |
| `--debug` | Print typed AST and, for run/build, unoptimized IR; run also prints timing |
| `--emit-ir FILE` | Save optimized IR with run/build; overwrite that output file |
| `-h`, `--help` | Show usage |

Debug output goes to stdout. `--emit-ir` is not available with `check`.

## Native libraries

```sh
lotus run --libs ./libs hello.lt
```

`--libs` **replaces** the default directory. Include `lotus-core` there if the program uses its functions. This loads native dynamic libraries, not `.lt` modules; custom libraries need [Lotus registration](/development/native).

Selection order:

1. `--libs DIR`
2. Environment variable `LOTUS_LIBS`
3. `LOTUS_RUNTIME_DIR`, recorded at compiler build time

The installer sets this to its `lib/lotus` directory. A manual CMake build defaults to the checkout's `libs/`; override it with `-DLOTUS_RUNTIME_DIR=/path/to/libs`. Reinstall if you move the installation directory.

## Executable builds

`build` uses LLVM to emit an object and `cc` on macOS/Linux or MSYS2 `clang` on Windows to link it. Set `CC` to another compiler executable if needed; supply a command or path without extra flags. `run` does not require the linker.

A subsequent build replaces the output. On macOS/Linux, native library directories are recorded in the binary; keep those libraries at their installed paths. On Windows, `build` copies registered runtime DLLs beside the executable; keep them together. Dependencies of custom DLLs must also remain available.

Build on the target OS and architecture. This is not cross-compilation, and LLVM/toolchain installation is not bundled into generated executables.
