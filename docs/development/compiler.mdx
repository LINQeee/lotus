```text
Source → Lexer → AST → Type checker → LLVM IR → Verify → Optimize
                                                        ├─ run: JIT
                                                        └─ build: object → linker → binary
```

`check` stops after type checking. See [CLI reference](/cli) for AST/IR inspection.

| Location | Responsibility |
| --- | --- |
| `src/main.c` | Arguments, source loading and compilation pipeline |
| `src/lexer/` | Tokens and source locations |
| `src/parser/` | AST and syntax |
| `src/type_checker/` | Types, scope and return paths |
| `src/llvm/generator/` | Expression and statement IR |
| `src/llvm/var_manager.*` | Variables and string cleanup |
| `src/llvm/llvm.c`, `executable.c` | JIT and executable builds |
| `src/native_loader/` | Dynamic libraries and function registration |
| `lotus-core/` | Native runtime and string ownership |
| `tests/` | Language behavior cases |
| `tools/lotus-test/src/` | Runner, assertions and memory instrumentation |

## Change a feature

1. Update syntax and AST only where needed.
2. Define type and scope rules in the type checker.
3. Generate IR consistent with those rules and string ownership.
4. Add focused tests and update the relevant language page.

Verify execution and diagnostics, not just C compilation. For ABI changes, rebuild the compiler, runtime and native extensions together.

`src/deprecated_or_experiment_files/` is excluded from the active build and is not a specification.
