Lotus checks source types before generating LLVM IR. Use this map to locate the code and tests for a language change.

```text
Source → Lexer → AST → Type checker → LLVM IR → Verify → Optimize → JIT
```

| Location | Responsibility |
| --- | --- |
| `src/lexer/` | Tokens, keywords and source positions |
| `src/parser/` | Expressions, statements and AST construction |
| `src/type_checker/` | Types, scopes and return-path analysis |
| `src/llvm/` | IR generation, variables, optimization and JIT |
| `src/native_loader/` | Native libraries and function registration |
| `src/utils/` | Diagnostics helpers and AST printing |
| `lotus-core/` | Runtime implementation and native interface |
| `tests/` | Executable feature cases |
| `tools/lotus-test/` | Test runner submodule |
| `benchmarks/` | Equivalent workloads across languages |
| `docs/` | Mintlify source pages |

## When changing a feature

1. Update the necessary lexer/parser/AST pieces.
2. Define its type and scope rules.
3. Generate IR consistent with those rules and string ownership.
4. Add a focused `.lt` test and update the relevant documentation page.

Source errors should be diagnosed before JIT execution. Verify generated IR when changing control flow. Build both sides when changing the runtime ABI.

The compiler prints IR before optimization and writes optimized `output.ll` after execution. This file is diagnostic output; a supported standalone executable workflow is not implemented.

<Note>
`src/deprecated_or_experiment_files/` is excluded from the active build. Do not use it as the current language specification.
</Note>
