title: "Benchmarks"
description: "Compare equivalent workloads and understand the timing boundaries."
---

```sh
sh benchmarks/run.sh
sh benchmarks/run.sh --quick --runs 2
sh benchmarks/run.sh --case strings --languages lotus,c,rust
```

Requires Python 3.9+ with its standard library. The runner compares **Lotus, C, Rust, Go, JavaScript, Python, Java and C#**. Missing toolchains are skipped; build failures, wrong checksums and timeouts are errors. No packages are installed.

## Workloads

| Case | Focus | Default iterations |
| --- | --- | ---: |
| `arithmetic` | Dependent multiply, add and modulo | 1,000,000 |
| `branches` | Data-dependent branches | 1,000,000 |
| `calls` | Recursive Fibonacci with changing input | 2,000 |
| `strings` | Bounded concatenation and content comparison | 100,000 |

## Read the table

| Column | Includes |
| --- | --- |
| `algo ms` | Median algorithm time inside the process |
| `min ms`, `max ms` | Observed algorithm timing range |
| `process ms` | Startup, loading, Lotus compilation/JIT, work, output and exit |
| `build ms` | One separate source build, outside measured executions |
| `vs best` | Algorithm median divided by the fastest successful median |

The algorithm timer excludes input setup and result printing. Lotus parsing and initial LLVM/JIT preparation happen before it. C uses `-O3`, Rust `opt-level=3`, Go its normal build, Java `javac`, and C# Release. Build caches are not normalized; Lotus toolchain/timer setup is recorded separately in JSON.

<Warning>
Every run is a fresh process: one discarded run, then five measured runs by default. This warms OS caches, not the next process's Java/Node/.NET JIT. Runtime JIT work and GC during the algorithm remain measured. These results are not a general ranking of languages.
</Warning>

Inputs are read at runtime and intermediate integers fit signed 32-bit values. Normal optimization is allowed. String representations differ: C allocates/copies/frees, Lotus uses ARC, Rust uses formatted concatenation, and managed runtimes may reuse buffers or use ropes. No RSS or allocation counts are measured.

## Options and output

| Option | Purpose |
| --- | --- |
| `--case NAME` | Select a case; repeat for multiple cases, or supply a directory |
| `--languages lotus,c,...` | Select implementations |
| `--runs N`, `--warmup N` | Measured and discarded fresh-process runs |
| `--quick` | One tenth of iterations for cases with a reference calculator |
| `--no-build-lotus`, `--compiler PATH` | Reuse or select a Lotus build |
| `--timeout`, `--build-timeout` | Deadlines in seconds; defaults 30 and 180 |
| `--output PATH` | New output directory |

Results go to `benchmarks/results/<timestamp>/`: `samples.csv` uses milliseconds; `results.json` uses seconds and includes commands and tool versions. Full logs are kept alongside them. The runner uses temporary sources and leaves your `test.lt` intact.

## Add a workload

Copy `benchmarks/cases/arithmetic` to a new case directory and edit equivalent implementations. Missing language files are skipped; code is not translated automatically.

Use `iterations`, `seed`, `description` and a known `expected` checksum in `case.json`. Remove `reference` when replacing the built-in algorithm:

```json
{
  "iterations": 1000000,
  "seed": 7,
  "description": "My workload",
  "expected": 12345
}
```

`12345` is a placeholder: replace it with your program's known result. Built-in `reference` names choose independent checksum calculators; fixed-checksum cases keep their iteration count under `--quick`.

<Accordion title="Program contract">
Read `BENCH_ITERATIONS` and `BENCH_SEED` before timing. Emit one result line after timing:

```text
@@BENCH 0.012345678 12345
```

The first value is seconds, the second is the integer checksum. Lotus uses `benchIterations()`, `benchSeed()`, `benchStart()` and `benchFinish(checksum)` from the benchmark-only native library.

Recognized files: `lotus.lt`, `c.c`, `rust.rs`, `go.go`, `javascript.js`, `python.py`, `Main.java`, `Program.cs`. C can include `timer.h`; Java defines `Main`. C# uses a temporary project with the installed SDK and cleared NuGet sources; Go disables module fetching and toolchain downloads.
</Accordion>
