## Install

Requires VS Code 1.85+. [Build a VSIX package](/development/extension#build-a-package), then use **Extensions: Install from VSIX** in VS Code.

## Configure the compiler

Install or build [Lotus](/quickstart), then open VS Code settings and search for **Lotus**.

| Setting | Default | Purpose |
| --- | --- | --- |
| `lotus.compilerPath` | `lotus` | Executable in PATH, an absolute path or a workspace-relative path |
| `lotus.librariesPath` | Empty | Optional runtime directory passed as `--libs` |
| `lotus.diagnostics.enabled` | `true` | Check files on open, save and while typing |
| `lotus.diagnostics.delay` | `300` | Delay after typing before checking, in milliseconds |
| `lotus.diagnostics.timeout` | `10000` | Check timeout in milliseconds |

For a compiler checkout, workspace settings can contain:

```json
{
    "lotus.compilerPath": "./cmake-build-debug/lotus",
    "lotus.librariesPath": "./libs"
}
```

On Windows, include `.exe` in the compiler filename. Do not add shell quotes to paths with spaces. In a multi-root workspace, relative paths resolve against the folder containing the document.

## Commands and errors

Use the command palette:

- **Lotus: Check Current File** checks the current editor text without saving.
- **Lotus: Run Current File** saves and runs it in a VS Code task.
- **Lotus: Build Current File** saves and builds an executable in a VS Code task.
- **Lotus: Show Compiler Output** opens the check log with the compiler command and working directory.

Compiler execution requires a trusted workspace. Syntax and navigation remain available without trust.

Checks include unsaved changes. For a new unsaved file, select Lotus as its language mode.

Errors with source positions appear in Problems and as underlines. Other errors appear in the Lotus language status and **Lotus** output channel. Each check reports the first compiler error.

If valid code reports `Unknown symbol: .`, check for an older compiler in `lotus.compilerPath`. Update it or point the setting to your current build.

## Highlighting

Classes, fields, parameters, variables and calls use distinct highlighting. Colors follow your VS Code theme.

## Completion and navigation

Completion, hover, go to definition and the outline use the current document. Completion supports typed variables, parameters, fields, methods, `this`, nested named receivers and array `.length`. Built-ins, keywords and snippets for classes, functions, conditions and loops are also available.

The declaration analyzer cannot infer receivers from arbitrary expressions or method return chains. Cross-file symbols, rename and formatting are unsupported. Incomplete code may yield incomplete suggestions.

The `.lt` file icon depends on your file icon theme.
