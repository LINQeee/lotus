## Register a function

Create `example.c` in the compiler checkout:

```c example.c
#include "lotus.h"

LOTUS_EXPORT int twice(int value) {
    return value * 2;
}

LOTUS_NATIVE_LIBRARY {
    LOTUS_FUNCTION(twice, LOTUS_I32, LOTUS_I32);
}
```

On macOS, build into the directory containing your runtime:

```sh
clang -dynamiclib -I lotus-core example.c -o libs/libexample.dylib
```

Create `example.lt` and run `lotus run --libs ./libs example.lt`:

```rust example.lt
print(twice(21))
```

```text Output
42
```

The loader calls each library's `lotusRegister` entry point. Export functions under their registered names. Keep lotus-core in the [selected library directory](/cli#native-libraries) for standard functions.

## Native types

| Lotus type | Tag | C representation |
| --- | --- | --- |
| `int` | `LOTUS_I32` | 32-bit signed integer |
| `long` | `LOTUS_I64` | 64-bit signed integer |
| `float` | `LOTUS_F32` | `float` |
| `double` | `LOTUS_F64` | `double` |
| `bool` | `LOTUS_BOOL` | `bool` |
| `string` | `LOTUS_STRING` | `LotusString *` |
| No result | `LOTUS_VOID` | `void` |
| Boxed native argument | `LOTUS_ANY` | `const LotusValue *` with type tag and payload |

`LOTUS_FUNCTION(name, result, args...)` registers a fixed signature. `LOTUS_VARIADIC` uses a leading argument count; follow `print` in `lotus-core/src/io.c` for its ABI. Boxed arguments are passed by pointer on every platform to avoid platform-specific struct calling conventions. The pointer is borrowed for the call; rebuild existing native libraries for this ABI. Native `any` parameters do not enable implicit language casts.

## String ownership

| Operation | Contract |
| --- | --- |
| Receive a string, including a boxed string | Borrow it for the call |
| Keep an argument beyond the call | Retain it; release when done |
| Return a new string | Transfer one owned reference |
| Return a borrowed string | Retain before returning |

`LotusString` stores `length`, `data` and `references`. `_stringRetain` and `_stringRelease` manage references. Zero references mark an immortal literal, not an unowned allocation. Do not mutate shared strings or return stack storage; reference counting is single-threaded.

`_concat` borrows its operands and returns a new owned string. The compiler also uses
`_concatOwned`, which consumes one owned reference to each operand and may reuse a
uniquely owned left buffer. This internal helper cannot be called from Lotus source.
`LotusString` layout and the public borrowed-argument ABI are unchanged.

## Array storage

Array storage uses the element's actual size: 4 bytes for `int`/`float`, 8 for
`long`/`double` and string pointers, and 1 for `bool` on supported platforms.
The compiler generates checked access using the internal runtime layout; rebuild
compiler and lotus-core together. Native code must use the array runtime helpers
rather than assume 8-byte slots or modify an array's length.

## Work on lotus-core

| Path | Purpose |
| --- | --- |
| `lotus.h` | ABI and registration macros |
| `library.c` | Language function registration |
| `src/` | Public runtime functions |
| `internal/` | Compiler helpers named with `_` |
| `utils/` | C-only implementation helpers |

`lotusStringCreate(length)` in `utils/string_utils.h` returns one owned reference with storage for the bytes and trailing NUL. Fill the bytes before returning the string. This helper is neither registered nor exported.

Add new C sources to the runtime's CMake target. [Build instructions](/development/build) and [tests](/development/tests) use the compiler checkout; standalone runtime builds also write to `../libs/`. After ABI changes, rebuild compiler, runtime and extensions together.
