## Register a function

Create `example.c` in the compiler checkout:

```c example.c
#include "lotus.h"

LOTUS_EXPORT int twice(int value) {
    return value * 2;
}

LOTUS_NATIVE_LIBRARY {
    LOTUS_FUNCTION(twice, LOTUS_I32, LOTUS_I32);
}
```

Build into the directory containing your runtime:

```sh
clang -dynamiclib -I lotus-core example.c -o libs/libexample.dylib
```

Create `example.lt` and run `lotus run --libs ./libs example.lt`:

```text example.lt
print(twice(21))
```

```text Output
42
```

The loader calls each library's `lotusRegister` entry point. Registered functions must be exported under their registered names. `--libs` replaces the library directory; retain lotus-core there for standard functions.

## Native types

| Lotus type | Tag | C representation |
| --- | --- | --- |
| `int` | `LOTUS_I32` | 32-bit signed integer |
| `long` | `LOTUS_I64` | 64-bit signed integer |
| `float` | `LOTUS_F32` | `float` |
| `double` | `LOTUS_F64` | `double` |
| `bool` | `LOTUS_BOOL` | `bool` |
| `string` | `LOTUS_STRING` | `LotusString *` |
| No result | `LOTUS_VOID` | `void` |
| Boxed native argument | `LOTUS_ANY` | `LotusValue` with type tag and payload |

`LOTUS_FUNCTION(name, result, args...)` registers a fixed signature. `LOTUS_VARIADIC` uses a leading argument count; follow `print` in `lotus-core/src/io.c` for its ABI. Native `any` parameters do not enable implicit language casts.

## String ownership

| Operation | Contract |
| --- | --- |
| Receive a string, including a boxed string | Borrow it for the call |
| Keep an argument beyond the call | Retain it; release when done |
| Return a new string | Transfer one owned reference |
| Return a borrowed string | Retain before returning |

`LotusString` stores `length`, `data` and `references`. `_stringRetain` and `_stringRelease` manage references. Zero references mark an immortal literal, not an unowned allocation. Do not mutate shared strings or return stack storage; reference counting is single-threaded.

`_concat` and `_stringEquals` support language operators. Lifetime helpers cannot be called from Lotus source.

## Work on lotus-core

| Path | Purpose |
| --- | --- |
| `lotus.h` | ABI and registration macros |
| `library.c` | Language function registration |
| `src/` | Public runtime functions |
| `internal/` | Compiler helpers named with `_` |
| `utils/` | C-only implementation helpers |

`utils/string_utils.h` provides `lotusStringCreate(length)`: one owned reference, storage for the bytes and trailing NUL. Fill the bytes before returning the string. This helper is neither registered nor exported.

Add new C sources to the runtime's CMake target. [Build instructions](/quickstart) and [tests](/development/tests) use the compiler checkout; standalone runtime builds also write to `../libs/`. Rebuild compiler, runtime and extensions together after ABI changes.
