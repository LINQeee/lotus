Requires Node.js 20+ and the [build toolchain](/quickstart). From the compiler root:

```sh
npm ci --prefix tools/lotus-test
node tools/lotus-test/bin/lotus-test.mjs
node tools/lotus-test/bin/lotus-test.mjs loops/for
```

The runner builds the compiler/runtime, then runs `.lt` files through `lotus run`. Each test uses its original source, a separate process and a temporary working directory. Runtime modes are prepared once per run in separate directories.

## Write a test

Place it under `tests/<feature>/`, with a descriptive filename:

```text ascending-iterating-for-loop.lt
// expect: "1\n2\n3\n"

for i in 1..3 print(i)
```

For rejected programs, use a diagnostic substring:

```text implicit-cast.lt
// error: "cannot assign float to double"

double value = 2f
```

All directive values use JSON. Exactly one `expect` or `error` is required.

| Directive | Meaning |
| --- | --- |
| `expect: "..."` | Exact program stdout, including final newlines |
| `error: "..."` | Exit 1 with this diagnostic before execution |
| `input: "..."` | Stdin text, followed by EOF |
| `ir: ["..."]` | Required text in IR before optimization |
| `log: ["..."]` / `no-log: ["..."]` | Required / forbidden stdout or stderr text |
| `entry-allocas: false` | Disable entry-block allocation checking for this case |
| `runtime: "normal"` | Use the configured runtime library |
| `runtime: "none"` | Load no runtime libraries |
| `runtime: "memory"` | Use the instrumented string runtime |

`runtime` and entry-allocation checks inherit config values when omitted. `expect` excludes debug output; use log assertions for stderr. Invalid directives report `DIRECTIVE ERROR` with the source location and skip execution of that case. Crashes, timeouts and missing execution markers fail the test.

## Run options and results

| Option | Effect |
| --- | --- |
| `--no-build` | Reuse compiler/runtime binaries; memory instrumentation still builds |
| `--compiler PATH` | Choose another compiler executable |
| `--timeout SECONDS` | Set the per-test deadline |
| `-v`, `--verbose` | List individual results |
| `-h`, `--help` | Show usage in a configured project |

Output uses colors and one summary per root group. A terminal spinner shows the current test; verbose mode and redirected output omit animation. Failures show details and log paths under `resultsDir`.

Exit codes: **0** pass, **1** failed cases, **2** setup or selection error.

## Configuration

`lotus-test-config.json` is located by searching upward from the working directory. All fields are required; values come from the config, not built-in defaults.

| Fields | Purpose |
| --- | --- |
| `testsDir`, `resultsDir` | Test and log directories |
| `compiler` | Compiler executable |
| `cmake` | CMake command/path; overridden by environment `CMAKE` |
| `runtimeBuild`, `runtimeLibrary` | Runtime build directory and library file |
| `timeout`, `setupTimeout` | Positive deadlines in seconds |
| `build`, `verbose` | Build before tests; list individual results |
| `runtime` | Default runtime mode |
| `entryAllocas` | Check that stack allocations stay in entry blocks |

Config paths are relative to the config file. CLI options override config; CLI `--compiler` is relative to the working directory. The checked-in config enables entry-allocation checks.

## Coverage

Feature folders cover syntax, types, expressions, scope, control flow, functions, strings and native calls. Add cases there; edit `tools/lotus-test/src/` only when changing the runner itself.

Memory tests build lotus-core with ASan/UBSan and allocation counters. `CC` selects Clang. LeakSanitizer is disabled and JIT code is not instrumented; these checks do not prove complete compiler-memory cleanup.

CLI tests separately cover run/build/check, files, runtime paths and IR export:

```sh
node --test scripts/test-cli.mjs
```

Build first, or run the language suite. `LOTUS_COMPILER` selects another CLI executable. Both suites run in the Git hooks.
