`docs/` is the shared documentation source for Lotus, lotus-core and lotus-test. READMEs only introduce each repository and link here. Pages use MDX; `docs.json` defines navigation and appearance.

## Preview and validate

Requires Node.js 20.17+ and npm:

```sh
cd docs
npm ci
npm run dev
```

Open the printed local URL. Before submitting a change:

```sh
npm run check
```

This checks Mintlify content, config and links. Execute changed language examples separately. Commit pages, assets and package files; keep generated caches and dependencies ignored.

Use `lotus` for Lotus code fences and `text` for output. The syntax grammar lives in `assets/lotus.tmLanguage.json`.

## Put information in one place

- **Get started:** installation, first run, CLI and current limits
- **Language:** syntax, behavior and runtime functions
- **Contribute:** workflow, tests, compiler internals and native extensions

Follow `AGENTS.md`: short examples with output, concise rules, links instead of repetition. Use Kotlin, React and Qwik as presentation references. Keep implementation details out of beginner instructions unless they affect use.

## Publish

1. Push the documentation to `LINQeee/lotus`.
2. In Mintlify Git settings, connect that repository and production branch through its GitHub App.
3. Set the docs subdirectory to `/docs`, without a trailing slash, and save.
4. Wait for a successful deployment and check the published pages. Future pushes to that branch update the site.

If replacing a Mintlify-hosted repository, download its content first. Local preview does not publish anything. See Mintlify's [GitHub setup](https://www.mintlify.com/docs/deploy/github) and [subdirectory setup](https://www.mintlify.com/docs/deploy/monorepo).
